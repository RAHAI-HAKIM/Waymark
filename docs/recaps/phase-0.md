# Phase 0 recap: Foundation

**Closed 15/09/2026**, build complete. What remains before Phase 0.5 is Hakim's final test
and analysis, and the resolution of the open findings and questions in `docs/status.md`.

A snapshot, not a live document (see `README.md` in this folder). Decisions are cited by
number; `docs/decisions.md` holds each one's reasoning and rejected alternatives.

---

## 1. What Phase 0 was for

The Build Plan's Phase 0 has no demo. It lays the foundation that every later phase would
otherwise get silently wrong:
- money and quantity arithmetic;
- identity;
- store scoping;
- the schema and its guards;
- the privacy boundary;
- the command pipeline;
- a fake store to develop and evaluate against.

**The exit test:** the solution builds with its architecture enforced; the store database
is created from empty with every guard; value objects are proven; the tenant key provably
never leaves; and a generator produces a plausible year that loads.

### 3.3 W10, the generator

Built step by step with Hakim reviewing every two or three steps. **How it works and how to
use it: `src/Waymark.Generator/README.md`.**

| Step | Built |
| :---- | :---- |
| S0 | `SeededIdGenerator` on a `TimeProvider` (F-3) |
| S1 | Projects, solution entries, architecture rules, CLI |
| S2 | Addressed randomness (SplitMix64 over FNV-1a, no shared RNG), distributions, simulated clock, calendar (Ramadan phases, pay cycle, events, opening intervals per day type) |
| S3 | `grocery-dz` catalogue enriched from Hakim's 399 real products (`tools/enrich-catalogue`); sourced configuration; strict loading and validation |
| S4 | Commissioning: reference data, 120 customers with consent events, opening stock |
| S5 | Demand, baskets, sales with the real money arithmetic, FIFO, substitution, cash sessions, shifts, `latent-demand.csv` |
| S6 | `NaiveShopkeeperPolicy`, supplier visits, late and short deliveries, batches, expiry write-offs |
| S7 | Discounts, voids, returns and refunds, store credit, on-account, paid-in/out, drops, miscounts, cycle counts |
| S8 | Outbox (`anonymous_basket`, gapless sequences), drain profiles, `sync_state`; sales identical under every profile |
| S9 | `report.md`, manifest completion, determinism of every output, the full-year run, StoreServer `/health` on a generated store |
| S10 | Hakim's review of the report; this recap; the generator guide; D-054 completed |

**Hakim's parameter decisions:**
- **S3–S4:** no 0% VAT class; sensitive flags deferred; the catalogue accepted as uniform;
  the Ramadan 1447 and Aïd al-Adha 2026 dates confirmed; objectors without consent under
  legal basis `contract`.
- **S5:**
  - baskets of 1–50 units with P(<7) = P(>7) = 0.45 and P(7) = 0.10, mean 7.2 (his "0.9"
    read as 0.45, since the three must sum to 1);
  - 18% of baskets against a regular; cash 95%, card 4%, wallet 1%;
  - a quarter of prices off the 5 DZD step, so tender rounding happens;
  - Ramadan Fridays open; the staff rota confirmed.

**The full year (seed 42, always on):**
- About 70 s: 392,896 rows, 145,635 CSV rows.
- 22,548 sales, 95.3% of wanted units sold. Lost demand runs 2–6% a month and creeps up,
  because the naive rule remembers stockout days as slow sales.
- 642 deliveries, spoilage about 0.9%.
- 440 returns, 208 voids, 14,328 tender-rounding rows.
- 22,548 baskets emitted and acknowledged.

**Verification:**
- Every invariant test was proven to fail by breaking its code (D-012).
- The breaks by step: S0–S4, 11; S5, 22; S6–S7, 29; S8–S9, 17.
- Two breaks first survived, and both exposed weak tests, not weak code:
  - a stale credit cache passed because every credit had been spent;
  - the dump's table exclusion passed because every profile had converged.
  Both tests were fixed.

## 6. Ways of working that held

- **CLAUDE.md is the short form of every rule; `decisions.md` is the argument.** A
  non-obvious choice gets an entry with what was rejected, before or with the code.
- **`status.md` is read first each session** and rewritten as work lands. Findings are rows
  closed by deletion.
- **Tests exist where errors are silent**, and every new one is proven to fail by breaking
  the code. A break the compiler catches does not count.
- **Hakim decides schema, arithmetic, privacy, sync and engine method.** Claude drafts,
  tests and proves. The generator's parameters were drafted as `guess`, with a note each,
  and reviewed by distribution rather than code.
- **Work in reviewed batches.** W10 ran in steps of two or three, each ending green with a
  review list.
- **Documents say what is true now; git keeps history.** Superseded text is removed.
  `c3531bf` holds the last long-form decision log.

## 7. What Phase 0.5 inherits

The walking skeleton: scan → cart → sale → stock movement and tier 1 → pseudonymise →
outbox → stub cloud → expiry evaluator → envelope → Integration Layer → Local Admin card →
decision written and logged. `status.md` §6 has the hop-by-hop table of what exists and
what is missing, and the decisions it needs from Hakim.

What Phase 0 hands it directly:
- **The money and stock pipeline** (value objects, schema, executor) for `CompleteSale`.
- **Contracts** for the outbox payload and the recommendation envelope.
- **The pseudonymisation boundary and key store**, still to be wired into a host.
- **A generated store** as fixture data for every screen and handler, an outbox with real
  basket payloads for the stub cloud, and `latent-demand.csv` with `NaiveShopkeeperPolicy`
  as the engine's answer key and baseline.
